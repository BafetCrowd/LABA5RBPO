Вариант 6. Репертуар театра и продажа билетов.

В этой работе я добавил вход и регистрацию с JWT-токенами:

- `POST /auth/login` для входа.
- `POST /auth/register` для регистрации.
- `POST /auth/refresh` для обновления пары токенов.

Для доступа использую access-токен, для обновления пары refresh-токен. Оба подписываю HS256. Access действует 15 минут, refresh 7 дней.

Сессии храню в таблице `user_sessions`. При обновлении старую запись перевожу в `USED`, новую создаю со статусом `ACTIVE`. При повторном использовании старого refresh сохраняю `REVOKED` и возвращаю 401.

Обновление выполняю в одной транзакции. При ошибке сохранения изменения откатываются. Из двух одновременных запросов с одним refresh успешно проходит только один.

Сохранил роли покупателя и администратора, проверку паролей и уникальность логина. Пароли храню в виде BCrypt-хешей. Настройки базы и ключ JWT вынес в `.env`, пример настроек оставил в `.env.example`.

Для проверки подготовил коллекцию запросов Postman и автотесты.

Учебный аккаунт: `admin / admin`. Адрес приложения: `http://localhost:8084`.
